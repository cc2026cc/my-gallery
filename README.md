# 荣昌陶艺 · 个人作品展厅

静态网站，部署于 GitHub Pages。数据不写死在页面里——网站每次打开时实时读取本仓库 `products/` 目录，**加新品只需上传资源文件夹，不用改任何代码**。

## 目录结构

```
my-gallery/
├── index.html          # 网站全部代码（视觉 + 数据逻辑 + 交互，单文件）
├── assets/             # 首页两扇窑门的门面大图
│   ├── tea-hero.jpg    # 细陶门面（手机 800px）
│   ├── tea-hero-pc.jpg # 细陶门面（电脑 1600px）
│   ├── clay-hero.jpg   # 粗陶门面（手机 800px）
│   └── clay-hero-pc.jpg
├── products/
│   ├── 细陶茶器/        # 分类一：茶器、茶壶、杯子等
│   │   ├── 01-粗陶柴烧坛香壶/
│   │   ├── 02-主人杯/
│   │   └── ...
│   ├── 粗陶花盆/        # 分类二：花盆、陶罐等
│   │   └── 01-国际盆/
│   └── yinzhang.png    # 「已结缘」印章图（放在 products 根目录）
└── README.md
```

首页是「窑门双开」：上门茶器、下门花器（电脑上是左右两扇）。
每个产品文件夹 = 网站里的一件展品。两个分类各自独立排序，**序号请从 01 开始编**。

## 上架新品的完整步骤

1. 在 `products/细陶茶器/` 或 `products/粗陶花盆/` 下新建文件夹，命名 `序号-名称`，例如 `03-柴烧西施`。
   序号决定排列顺序，同类内不要跳号重复。
2. 放入产品图片（jpg / webp 均可）。建议长边 1600px、单张 300KB 以内，手机打开才快。
   图片在详情页的显示顺序规则：**按文件名中的数字大小排**——文件名末尾带
   "-序号" 的按序号数字升序显示（-0 → -1 → -2 → … → -10，两位数也不会乱）；
   没有 "-序号" 的（如 `01.jpg`、`_DSC8924.JPG`）排在有序号的后面，按文件名字典序排。
   建议同一文件夹统一用一种命名，不要混用。
   每件作品的第一张图会同时用作展厅里的小封面。
3. **封面图**：放一张命名为 `thumb.jpg` 的图（建议 480px 左右方形小图）。
   没有 thumb.jpg 时网站会自动用第一张图兜底，但裁切效果不如专用封面。
4. 放入介绍文件 `info.txt`（或 info.md，支持 Markdown）：
   - 第一行 = 产品标题（显示在详情页大标题）
   - 空一行后写正文
   - 正文里出现「**已结缘**」三个字，该作品自动盖上已结缘印章、入口按钮变为「已售出」状态
5. 上传完成，等 1～2 分钟刷新网站即可见。

> 示例结构：`products/粗陶花盆/02-陶罐/thumb.jpg` + `01.jpg` `02.jpg` + `info.txt`

## 修改与维护

- **换门面大图**：替换 `assets/` 里对应的图片（保持文件名不变），建议手机 800px 宽、电脑 1600px 宽，JPEG 质量 70 左右，单张 250KB 以内。
- **改分类名**：显示名在 `index.html` 里搜 `茶器` / `花器`（门上大标题、展厅标题、网页标题、图片说明各一处）；`products/` 下的文件夹名不用动——网站按文件夹名认分类，文件夹改名要连推送一起删旧建新，没必要。
- **下架作品**：把对应产品文件夹改名（前面加个 `_`，如 `_03-柴烧西施`）或移出 products，网站即不再显示，文件保留可随时恢复。
- **回滚**：GitHub 仓库页面 → Commits 历史 → 找到改动前的版本 → Browse files → 手动下载旧版 index.html 传回。

## 技术说明（给未来的维护者）

- 零依赖单文件：无框架、无网络字体、无构建步骤，index.html 即全部。
- 数据来源：GitHub Contents API 实时读取 products 目录（thumb 结尾文件识别为封面）。
- 交互：hash 路由（网址可直达具体作品）、自研灯箱、图片三级预加载、「已结缘」关键词自动判定已售。
